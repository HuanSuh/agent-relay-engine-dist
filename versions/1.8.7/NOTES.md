# agent-relay-engine 1.8.7 릴리스 노트

바뀐 범위: 1.8.6 → 1.8.7

### core

- **`dispose()` 가 보낸 세션 기록 쓰기를 비운다.** 1.8.5 부터 턴 경로의 세션 기록 쓰기(턴 수·사용량·Claude 의 `ext.claude.cliCostUsd`)는 완료를 기다리지 않는데, `dispose()` 는 그 쓰기를 기다리지 않고 끝났다. 그래서 `SIGTERM` 에 `dispose()` 직후 끝나는 호스트는 마지막 턴의 기록을 잃을 수 있었고, 다시 띄운 엔진에서 `--resume` 한 첫 턴의 Claude `usage.costUsd` 가 낡은 직전 누계와의 차이로 계산돼 과다했다(같은 세션 두 턴이 `0.10`·`0.15`, 재기동 뒤 누계 `0.40` 인 턴이 `0.15` 대신 `0.30`). 1.8.7 의 `dispose()` 는 세션마다 프로세스를 내린 뒤 보낸 쓰기가 저장소에 닿기를 기다린다. 세션들을 함께 기다려 **`dispose()` 가 최대 5초 더 걸릴 수 있다**(세션 수와 상관없다). 저장소가 그보다 오래 멈추면 기다리지 않고 끝난다. 종료 처리에 시간 상한을 둔 호스트는 `termGraceMs` 기반 정리 시간에 5초를 더해 잡는다. 1.8.5·1.8.6 에서 이미 과다하게 남은 세션 합은 고쳐지지 않는다. 한 세션의 정리가 던져도 다른 세션의 정리와 비우기를 끝까지 마친 뒤 세션 순서로 첫 오류를 던진다(나머지 오류는 버린다. 1.8.6 은 먼저 난 오류에서 바로 던졌다). 정리 상한을 넘겨 강제로 닫힌 턴이나 늦게 닫힌 프로세스가 `dispose()` 뒤에 남기는 기록은 이 비우기에 들지 않는다 — 호스트가 바로 끝나면 잃는다. `dispose()` 뒤 늦게 나가는 기록(그것과 5초 상한을 넘겨 줄에 남은 쓰기)은 같은 저장소로 다시 띄운 엔진의 기록을 덮을 수 있다 — 같은 호스트에서 엔진을 다시 띄우면 옛 엔진의 `dispose()` 를 기다린 뒤 띄운다. 그래도 저장소가 5초 넘게 멈췄거나 강제로 닫힌 턴이 있으면 덮일 수 있는 창이 남는다. `evict()`·유휴 정리는 세션을 엔진에 남기므로 바뀌지 않는다. 타입·export 는 바뀌지 않았다.
